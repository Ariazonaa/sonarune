# AGENTS.md

Instructions for AI coding agents working on Sonarune — Claude Code, Codex,
GitHub Copilot, Cursor, Gemini CLI or any other — and for the people steering
them. This file is the single source: `CLAUDE.md` and `GEMINI.md` only import
it, `.github/copilot-instructions.md` only points here. Change the rules here,
nowhere else.

## Working rules

**Reporting**
- Report what actually happened. Say which checks ran and what they showed,
  and say plainly what was *not* verified ("built, but not tested in the
  running app"). Never present a check as passed that did not run.
- Ask only when a decision genuinely belongs to the maintainer — scope,
  product behaviour, anything irreversible or public that these rules do not
  already cover. Otherwise pick the sensible default and name it in the report.
- Commit messages say what was done, accurately; length is free. **No AI
  co-author trailer** — no `Co-Authored-By: Claude …` or the like, and no
  "Generated with …" line in pull requests: GitHub would list the agent as a
  contributor. The AI disclosure in the README covers how the project is
  built; commits stay under the maintainer's name.

**Verifying**
- Run the gates the change touches before committing: Rust → `cargo fmt
  --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --lib`;
  frontend → `npm run check` (0 errors, 0 warnings), `npm run test`; a
  production build when bundling, the CSP, assets or the installer change.
  The full `npm run verify` runs before anything is published or a pull
  request is opened.
- Where a change can be seen, also exercise it in the running app — against a
  real Jellyfin 10.11 server or the stand-in in `scripts/devserver/`.
- Get an independent second opinion (another agent or model) before landing
  changes to the audio hot path (`player/`), TLS and certificate pinning
  (`tls.rs`), the updater and installer, data migrations (`legacy.rs`, the
  store) or anything else security-relevant.

**Scope and safety**
- Dependencies may be added or updated when the task needs them. Keep the
  lockfiles committed, stay GPL-3.0-compatible (permissive licences preferred),
  check for known advisories, and name every dependency change in the report.
- Tags and releases are cut only when the maintainer asks.
- Planning and bugs live in GitHub issues.
- Never commit secrets, tokens, personal data or machine-specific paths.

## Project

Sonarune is a Windows-first Tauri 2 desktop music client for Jellyfin (server 10.11+), built as a faster/stabler replacement for Feishin. Svelte 5 (runes) + Tailwind v4 frontend, all real work in Rust.

## Commands

```powershell
npm run tauri dev        # run the app (Vite on port 1420 + cargo run; rebuilds on change)
npm run check            # svelte-check (0 errors, 0 warnings is the bar)
npm run test             # frontend unit tests (Vitest + jsdom)
npm run build            # frontend production build (also a good type smoke test)
npm run verify           # the full quality gate: check + test + fmt + clippy + cargo test + build
cargo clippy -- -D warnings   # in src-tauri/ — warnings are errors here
cargo check              # in src-tauri/
npm run tauri build      # release build + NSIS installer
```

`npm run verify` (`scripts/verify.mjs`) is the automated quality gate — the same
checks CI runs (`.github/workflows/ci.yml`, Windows), fail-fast. It needs cmake +
cargo on PATH for the Rust gates. The gate list and the manual live-test matrix
against Jellyfin 10.11.x live in `docs/testing.md`. Frontend tests sit next to
their module as `*.test.ts` (Vitest); mock Tauri commands by mocking
`@tauri-apps/api/core` `invoke` (see `src/lib/api.test.ts`).

`cargo test --lib` runs the unit tests (DSP, opus decoder, fades, scrobble rules, null-sink gapless continuity, queue shuffle/undo/dedup permutations, smart-view resolver, cert fingerprint/normalize, download part-file naming). There's also an ignored live smoke test (`api/mod.rs` mod `smoke`) that exercises the real server contract for the browse/playlist/artist/stats **and discovery/smart-view/collection** flows — run it against a real 10.11 server with `SONARUNE_TEST_URL=… SONARUNE_TEST_USER=… SONARUNE_TEST_PASS=… cargo test --lib smoke -- --ignored --nocapture` (it creates and deletes a temporary "delete me" playlist).

The frontend build output MUST stay in the project's `build/` dir: `frontendDist` in `tauri.conf.json` is `../build`, and Tauri embeds it into the binary at build time. Pointing `frontendDist` at an absolute path outside the project silently breaks that embedding — the *installed* app then shows an empty page / directory listing (dev is unaffected, it loads from `devUrl`). The `ENOTEMPTY` the adapter's rimraf occasionally throws on slow or networked file systems is handled by a retry-capable pre-clean (`scripts/clean-build.mjs`, run first in `npm run build`), not by moving the output. If your checkout sits on slow storage, redirect the **Cargo target** instead — see `src-tauri/.cargo/config.toml.example`.

Discord Rich Presence was removed; the module is archived under `archive/discord-rpc/` with re-integration notes.

The app mark (a bold S whose lower stroke ends in a tilted note head) is **generated**: `scripts/make-logo.mjs` describes it once as geometry and rasterizes every size natively from a distance field -- the whole `src-tauri/icons/` set including a hand-written `.ico`/`.icns`, `static/favicon.png`, `docs/logo.{png,svg}` and `src/lib/components/BrandMark.svelte` (used by the sidebar and the sign-in screen). Change the mark or `ACCENT` there, never the outputs, then re-run it **and** `scripts/make-installer-art.mjs`, which derives the setup art from `icons/icon.png`.

The NSIS installer is branded (custom header/sidebar art, `installerIcon`, de/en language selector, `currentUser` install) via `bundle.windows.nsis` in `tauri.conf.json`. The header/sidebar bitmaps in `src-tauri/installer/*.bmp` are **generated** (24-bit BMP3, the format NSIS requires) from the app logo by `scripts/make-installer-art.mjs` (`node scripts/make-installer-art.mjs`, needs the `pngjs` devDep). Re-run it if the logo/brand changes; it also drops PNG previews in the temp dir.

**Environment gotchas:**
- Building needs **libclang** too (`signalsmith-stretch` runs bindgen); clang-sys finds the one in VS Build Tools (`VC\Tools\Llvm\x64\bin`) on its own.
- Building needs **cmake** on PATH (the `opus` crate compiles bundled libopus). It's in the user PATH already (VS Build Tools CMake); if a build complains, prepend `C:\Program Files (x86)\Microsoft Visual Studio\2022\BuildTools\Common7\IDE\CommonExtensions\Microsoft\CMake\CMake\bin`.
- **CI installs the latest `stable` Rust on every run; a pinned local toolchain does not follow.** A lint introduced in a newer clippy therefore fails CI while the local `cargo clippy --all-targets -- -D warnings` stays green — check the CI log's `rustc` version before assuming a flaky run.
- **Unit tests must not reach code that needs the Tauri runtime** (a call through an `AppHandle`, such as `commands::renew_session`): the test binary then imports `TaskDialogIndirect` from comctl32 and, having no manifest, does not start at all (STATUS_ENTRYPOINT_NOT_FOUND — every test of `cargo test --lib` lost at once). Hand such a call in as a hook, the way `download.rs` takes its event sink and its session renewal.
- If port 1420 is stuck after a killed dev run, kill the owning process (`Get-NetTCPConnection -LocalPort 1420`).
- To leave the dev app running beyond a tool-call timeout, spawn it detached: `Start-Process cmd -ArgumentList "/c","npm run tauri dev"`.
- Don't run `npm run verify`/`npm run check` while `tauri dev` is up: both compile Paraglide into `src/lib/paraglide` and the two runs trip over each other (`ENOTEMPTY`, then a 404 on `messages.js` in the dev app). `npm run i18n:compile` repairs it. Its `--strategy` must match `vite.config.js`, or the dev app falls back to English.

Releases are cut by `.github/workflows/release.yml`, not by hand: push a `v*`
tag whose version matches all three manifests (package.json, tauri.conf.json,
Cargo.toml — the workflow refuses the build otherwise) and a **draft** release
appears with the NSIS installer, a portable zip and `latest.json`; review it
and publish by hand. A manual run builds the same way and creates nothing,
which is how to check the release path without cutting a release. Keep
`CHANGELOG.md` current in the same commit that bumps the version.

**Moving a tag that already has a release runs the workflow again**, and its
last step calls `gh release create` without asking whether that release exists.
On 22.09.2026 a force-pushed `v0.5.0` therefore produced a second, draft
release next to the published one — harmless, invisible to others, and easy to
miss. The published release and its assets were untouched. If a tag has to
move, delete the draft afterwards, and do not re-run a failed one: a successful
re-run only makes another draft.

For **winget**, `node scripts/winget-manifest.mjs` writes the three manifests
of a *published* release into `winget/manifests/` — download URL and date from
the GitHub API, checksum from GitHub's per-file `digest` and re-computed against the
downloaded installer, the ARP entries read out of `tauri.conf.json` so they
cannot drift from what the installer actually registers. Submitting is by
hand: fork microsoft/winget-pkgs, copy `winget/manifests/*` over its
`manifests/`, open a pull request. Every version needs its own.

The installed app **updates itself** (`src-tauri/src/updater.rs`, Settings →
Updates). `plugins.updater` in `tauri.conf.json` carries the endpoint
(`releases/latest/download/latest.json`) and the **public** minisign key; the
release workflow signs the installer with the private key from the
`TAURI_SIGNING_PRIVATE_KEY` secret and writes `latest.json` next to it. The
build never sees that key: one job builds with a read-only token, a second
signs the finished installer with `tauri signer sign` in a step that runs
nothing else and checks the signature against the public key, a third drafts
the release; a local `npm run tauri build` needs no key. The
check and the install are our own commands rather than the plugin's JS API, so
they go through the normal ACL generation and no secondary window can reach
them. Three rules live in the code and should stay there: never install while
the player is playing or loading (it is checked again after the download),
send the player's final reports before the installer kills the process and
start no track after them (`updater::hand_over` and `updater::handing_over` —
undoably, unlike `flush_before_exit`, because a blocked installer leaves the
process running), and refuse in a portable copy
— recognised by the absence of the NSIS `uninstall.exe` next to the exe —
instead of silently turning it into an installed one. `requireSignedVersion`
is on: the plugin rejects an installer whose signature does not name the
version `latest.json` announces, or names none. CLI 2.11.5 and later record
it in the trusted comment, as a tab-separated `version:…` after the timestamp
and the file name; a release signed by an older CLI, or by hand without it,
would be refused by every installed copy.

**Update channels** (`DesktopSettings::update_channel`, Settings → Updates):
stable asks only `plugins.updater`'s endpoint, through a version comparator
that also turns down a version with a pre-release part, so a beta published
without the pre-release mark by mistake reaches no stable install. Beta asks
that endpoint and `plugins.sonarune.betaEndpoint` (`beta.json` on the fixed
pre-release `beta-channel`) and takes the newer answer (`updater::newer_of`);
one of them failing does not fail the check. A tag with a pre-release version
(`v0.7.0-beta.1`) is drafted as a pre-release (`--prerelease --latest=false`),
and `.github/workflows/beta-channel.yml` copies its `latest.json` to
`beta.json` once it is published — only forward, except on a manual run with
a tag, which is the rollback. No GitHub API: its 60 requests an hour are per
address. The last answer is kept per channel (`get_known_update`), and the
winget script refuses pre-releases.

## Ground rules (from the project decisions — do not violate)

- **The WebView never touches audio or HTTP.** All server traffic (auth, browsing, covers, streams) goes through Rust/`reqwest` (tokens never in the DOM). Audio is decoded and played in Rust (Symphonia via rodio). Self-signed home servers are handled by **per-server SHA-256 certificate pinning** (`src-tauri/src/tls.rs`): a custom rustls `ServerCertVerifier` validates against the OS trust store first and accepts an untrusted leaf only when its fingerprint was user-confirmed (stored per `server_url` in SQLite). `connect` returns `ConnectResult::CertUntrusted { fingerprint }` for the login prompt; the legacy `accept_invalid_certs` flag now means "auto-trust this server on first use" (also migrates pre-pinning installs). That flag is only ever **kept while the server has a pin** (`Store::settle_auto_trust`, applied after every sign-in, Quick Connect, re-login and restore): a login that goes through with nothing pinned proved a public certificate, and a stored flag would let a later silent re-login pin whatever an attacker presents. A confirmed fingerprint — and likewise one trusted automatically on first use, in a sign-in, Quick Connect, re-login or restore — is accepted in memory for that one login attempt and pinned only after the login succeeds, only if the server actually presented it, and it **replaces** the server's previous pin (`Store::pin_fingerprint`); the session client is then rebuilt with exactly the stored pins. Settings → Trusted certificates lists and forgets pins (`list_trusted_certificates` / `forget_trusted_certificate`); forgetting the active server's pin signs out. Settings → Account signs out (`disconnect`: token revoked, credentials and queue dropped; settings and pins stay). Public certificates are checked by the OS's own verifier (`rustls-platform-verifier`, built once per process — on Windows CryptoAPI, which fetches a missing root on demand and honours distrusted ones); where none can be built, by webpki over the OS trust store, and with no anchors at all (a Linux/macOS system without a CA bundle) only pinned leaves pass instead of the client failing to build. **Do not** reintroduce blanket `danger_accept_invalid_certs` — route new HTTP clients through `tls::apply`, which also sets the proxy policy (`system_proxy.rs`: the Windows bypass list is read the way WinINet reads it — loopback, `<local>` and address wildcards such as `10.*` go around the proxy as they do in the browser — on top of reqwest's own reading, so nothing goes through the proxy that did not before).
- **Clean-room vs. Feishin**: never copy Feishin code or assets — concepts only. Sonarune is GPL-3.0-or-later, so this is no longer a licensing necessity, but the project was built clean-room and stays that way; lifting code now would misrepresent its provenance.
- Jellyfin auth uses **only** the `Authorization: MediaBrowser ..., Token="..."` scheme (legacy `X-Emby-*` headers are being removed server-side). `userId` goes in query params, not paths.
- All user-facing strings live in `messages/{en,de}.json` (Paraglide; `import { m } from "#lib/paraglide/messages.js"`). No hardcoded UI strings, including aria-labels.
- No Windows-only shortcuts in architecture — Linux/macOS stay possible (e.g. souvlaki also does MPRIS).
- **The app is AMOLED dark, one theme, no light mode.** UI colors only via the design tokens in `src/app.css` (`@theme` block), never hardcoded hex in components. The surface ladder is `base` (`#000`, window ground) → `panel` (chrome) → `card` (panes) → `panel-2` (hover/raised), all **opaque** — a translucent fill over black reads grey. `edge` is the hairline. Never use `white`-alpha utility classes (`bg-white/10`, `ring-white/10`, `accent-white`) for highlights/hovers — use the `ink` token (`bg-ink/10`, `accent-ink`, `text-(--color-base)`); `src/lib/designTokens.test.ts` fails the gate on any `-white/` utility. Opaque `text-white` on a colored surface (a red button, a generated hue gradient) is fine.
- **Never write `text-base`.** Because of the `--color-base` token, Tailwind compiles it to `color: var(--color-base)` — text in the background color, and no font size. 16px is `text-md` (own token); the base color as text is `text-(--color-base)`. `src/lib/designTokens.test.ts` fails the gate on any `text-base`.
- **Two surface classes carry the look** (`app.css`, unlayered so a `shadow-*` utility can't drop them): `.surface` is the chrome hairline (sidebar, `main`, player bar, queue, lyrics), `.overlay` is the floating one (fill + backdrop blur + hairline + depth) for dialogs, popovers, the palette, toasts and the download panel — it brings its own background, so don't add `bg-panel-2` next to it. Radii are capped by the panel they sit in: `rounded-panel` (12px) for chrome, `rounded-overlay` (10px) for overlays, nothing rounder inside. The `short:` variant (viewport ≤ 56rem high) hides secondary rows in low windows — the app allows 600px.
- **Floating UI declared inside a page goes to `<body>`.** `.overlay` is the only surface left with a `backdrop-filter`, which makes it the only containing block for `position: fixed` — anything fixed rendered inside one would land offset and scrolled away. Use `Popover.svelte` for menus/popovers and the `portal` attachment (`lib/portal.ts`) for modals, always on an element *inside* a wrapper that stays in place (never on a block's top-level node); that also keeps the overlays themselves out of each other.
- **Remote visualizer presets are code.** Butterchurn compiles preset equations with `new Function`, in a window that can invoke every command. The online "Butterchurn Weekly" entries stay behind the explicit, persisted opt-in (`sonarune.vis.remotePresets`, default off, `controller.ts` `#loadEntry` is the single gate) — never list or load a remote preset without it. They are downloaded in Rust (`fetch_weekly_preset`, `commands_visualizer.rs`: fixed S3 base, no redirects, size cap, gzip) and handed to the WebView only when their SHA-256 matches the pinned manifest `src-tauri/src/weekly_presets.json`; after updating `butterchurn-presets-weekly` (or on a "changed on the server" error) regenerate it with `node scripts/pin-weekly-presets.mjs` and review the diff.
- **Persisted names are user data.** The app `identifier` (it names the data directories and the WebView2 profile), the database file, the keyring service and the `localStorage` keys (`sonarune.*` / `sonarune:*`) decide where an install's state lives. Renaming one without a migration silently signs users out and resets their settings. `src-tauri/src/legacy.rs` and the pre-paint script in `app.html` carry the Jellysic → Sonarune move; follow that pattern (move only while the new location is empty, release builds under the real identifier only) and add a test.
- **A Content-Security-Policy is set** (`tauri.conf.json` `security.csp`, plus `devCsp` with the Vite HMR socket): scripts only from the app (`'unsafe-eval'` stays for Butterchurn), images from the app, `data:`/`blob:` and `jfimg`, connections only to IPC and `jfimg`. A new origin, asset type or worker needs a matching CSP change — and a wrong CSP shows up only in the *installed* build (blank window or silently missing images/visuals), so check a release build after touching it.

## Architecture

Two worlds connected by Tauri commands (UI → Rust) and events (Rust → UI):

**Rust (`src-tauri/src/`)**
- `api/` — thin typed Jellyfin client (`JellyfinClient`): auth, items/albums/search, images, playback reporting, stream URL building. Jellyfin wire DTOs are PascalCase (`api/types.rs`), everything sent to the frontend is re-mapped to camelCase DTOs.
- `player/` — the heart. A dedicated OS thread (`sonarune-player`, `player/mod.rs`) owns the rodio output, the **queue (single source of truth)**, playback reporting, and Windows SMTC (souvlaki, needs the main window HWND). It receives `PlayerCommand`s over an mpsc channel; a 400 ms `recv_timeout` tick drives position events, throttled progress reports (~10 s), prefetch scheduling, and end-of-track bookkeeping. Sources are opened **asynchronously** on short-lived threads (`player/source.rs`) and delivered back as `SourceReady` commands; a `generation` counter invalidates stale opens — never block the command loop. **Gapless**: the next track is opened ~20 s before the boundary and appended to the same `rodio::Player` ~3 s before it; `sink.len()` dropping to 1 signals the transition (rodio's `get_pos` tracks the current source, so position resets automatically). **Crossfade** (opt-in via `PlaybackSettings`) instead overlaps the tracks on a second `rodio::Player` with gain ramps from `player/fade.rs` (a sample-accurate `FadeSource` wrapper steered via a shared handle — also used for click-free pause/resume). **Decoding runs off the audio callback** (`player/source/feed.rs`): every source has a decoder thread (`sonarune-decode`) that decodes into a lock-free SPSC ring (`rtrb`, 1.5 s) through the conversion stage `player/source/resample.rs`: the ring holds the decoder's audio at the output's rate, in the channel count the decoder started with — rubato's synchronous FFT resampler (Blackman-Harris², blocks of ≥ 1024 frames at the lower rate), or bit-exact passthrough with no delay when the rates match (rates with too little in common for an FFT block of ≤ 131 072 frames: rubato's sinc resampler; a rate outside 4–768 kHz, i.e. a broken header, is not played; a sample that is not a number enters as silence). Its delay is cut off and its tail played out, with the edge frames held rather than silence, so a track is `resample::converted_len` frames long (to the nearest frame) and a gapless hand-over loses or adds no sample At a gapless append the player couples the two tracks (`source::couple` → `feed::FeedHandle::couple`, a `Link` between the decoder threads): the playing track's resampler plays out into the next track's first frames (its `Head`, kept by every source started at 0) instead of held ones, and the next track, if resampled, is converted once more from the frames its thread kept since its start (no decoder seek), beginning on the playing track's last frames (`Tail`) on the output grid that one ended on — two tracks at one rate come out exactly as one piece; between two rates the frames are interpolated across the seam (`resample::Seam`). The coupled start goes into a ring of its own that is offered to the very source it was made for (`Shared::offer_for`, one atomic swap at its first pull; `reposition` withdraws an offer); a source whose coupled ring is not ready at its first pull plays its pre-filled ring as if nothing had been coupled, so a coupled hand-over is never later than an uncoupled one. A resampled track with nothing coupled yet holds its resampler's tail back while its ring holds more than 0.5 s. A seek restarts it; a mid-stream rate change plays the old one out first. The rate belongs to each ring: `source::reposition` takes the rate of the output the source moves to, and `Worker::refit` moves a source that was opened for an output replaced while it loaded. What the mixer pulls (`RingSource`) only reads the ring — atomics and ring pops, nothing that allocates, locks, logs or does I/O; keep it that way — and plays silence while it is dry, so a stalled download silences that source alone; it ends only once the decoder is done and the ring drained. That silence is no media time: `position_ms` takes `DownloadProgress::silence` off rodio's `get_pos`. A native seek (`sink.try_seek`, whenever the stream has a length, downloaded or not) is a numbered request to the thread: the ring is emptied, a read waiting for the download is cut short (`feed::Interrupt`), and the source is silent until the target's audio is in; a seek the decoder cannot do reopens the track there. `restart_at` (a seek in a live transcode or during a beat lead-in, any reopen at a position, e.g. after an output-device switch) moves a seekable source with a working decoder onto a new ring of the same decoder and download (`source::reposition`, same play session) — nothing is downloaded again. Otherwise the track is opened anew: a live transcode via `startTimeTicks`, and a stream that broke off, or whose decoder crashed or failed a seek, positioned on the open thread (Jellyfin ignores `startTimeTicks` for direct play); `position_offset_ms` tracks media time either way. A decoder thread ends when its source is dropped or its download let go; a decoder that panics ends its track with the "cannot play" error and the queue moves on. Queue edits bump only `prefetch_generation`; bumping `generation` there would also drop the current track's own open. Output device is user-selectable, stored by cpal's device id (on Windows the endpoint id; two devices can share a name like "Speakers") plus its full name as last seen, and the per-device sound profiles (`audio_profiles.rs`) use the same id; they are read entry by entry, so an unreadable entry costs only itself (it is written back unchanged), and a value that cannot be read at all is set aside under `audio_profiles_unreadable` before the first save. Windows lists a device under a new id now and then, mostly with the old name (a re-paired Bluetooth headset, a USB device without a serial number in another port, a driver with one endpoint per sample rate): `resolve_output` then takes the only listed device of that name, and a profile moves along from an id that is no longer listed. A 0.6.0 value (cpal's bare endpoint name) still resolves to the first device of that name and is rewritten to the id when it opens. `open_output` installs a cpal error callback; `handle_output_failed` first reopens the configured device when its stream had run ≥ 10 s (a reconfigure or driver reset), else falls back to the default device (debounced) and resumes at the current position. A fallback never moves back by itself — Settings offers "Switch back" (`restore_output_device`). "System default", and a fallback, follow a change of the Windows default device (its id polled every 2 s on the tick; a new default that does not open is retried a few times, quietly). With nothing audible for `IDLE_OUTPUT_CLOSE` (5 min: paused or stopped, no crossfade tail or release ramp, no output failure pending), `watch_idle_output` closes the stream (`Output::close`), because a running WASAPI render stream holds Windows' "audio stream in use" power request and keeps the machine awake. A paused track drops its player and keeps its position, play session and listen clock (status `Paused` with no sink); if its download is complete it also keeps that download and its decoder thread, parked on a ring nothing pulls (`source::park`, dropped by `drop_stale_parked` once the track is anything but paused without a player). Play goes through `reopen_output` (the configured device, also by name, else the default with a fallback; an active fallback stays) and then resumes the parked source on a new ring at the output's rate (`Parked::resume` → `source::reposition`, no server needed), or else `restart_at`, which opens the track afresh — in the same play session, fading in from silence (`fade_in_arrival`); a reload that fails leaves the track paused with its session. Every path into Loading opens the output first, so no player joins a closed mixer. While closed, the default is not followed, a failure of the closed stream is ignored, a seek only moves the resume point, a device picked in Settings is opened but the track loads only on Play, and `audio_devices::active_device` stays set for the profiles and Settings. Decoders: Symphonia via `rodio::Decoder` (flac/mp3/vorbis/wav, gapless flag on) — except an MP3 whose bitrate is not constant (`source/mp3.rs` `bitrate`), which our demuxer `source/mp3/demux.rs` reads: Symphonia's MpaReader takes in the header frame (delay, padding, length as before), Symphonia's MP3 decoder decodes, and a frame index noted while reading turns a seek back into a jump; decoding starts at the main data of the frame 1152 samples before the target (the reservoir window is sized by its 511 bytes), so the landing is bit-exact; a constant one keeps Symphonia's coarse seek; if the demuxer cannot take a stream, rodio's decoder does — or our libopus-backed `player/opus.rs` for Ogg-Opus (probe-based, Symphonia fallback). Source chain: decoder → `source/resample.rs` (both on the decoder thread) → ring → `RingSource` → `player/dsp.rs` (normalization, 10-band EQ in double precision, since it runs at the output's rate; live via revision counter, changes glide over 10 ms; no clamp, only a NaN guard) → `player/fade.rs` → `player/tap.rs`. Each player reaches the mixer through `player/uniform.rs`: rodio's channel conversion without rebuilding it — and allocating — at every span (spans cut to whole frames); a rate other than the output's (only a live transcode opened for a replaced output) is converted linearly, as rodio did. The players mix into one mixer at the device's format, which reaches the device through `player/tempo.rs` and the output limiter `player/limiter.rs` (2 ms look-ahead, bit-transparent below full scale) — the last stage, so a crossfade or a boost that adds up past 1.0 is turned down instead of clipped.
- Lyrics: `GET /Audio/{id}/Lyrics` mapped to a camelCase `LyricsDto` (line + word-cue timestamps in ms); rendered by `src/lib/components/LyricsView.svelte` (panel + fullscreen variants, auto-scroll, click-to-seek) fed by `src/lib/state/lyrics.svelte.ts` (LRU cache, plus the per-track manual sync offset shared by every lyrics view and persisted via `lib/lyricsOffset.ts`) and `player.estimatedPositionMs()` (extrapolates between 400 ms state events). `src/lib/ambient.ts` extracts two cover colors for the now-playing backdrop — this needs the `Access-Control-Allow-Origin: *` header on jfimg responses (canvas taint).
- Session sharing: `SharedSession = Arc<RwLock<Option<Arc<JellyfinClient>>>>` is shared between commands and the player worker (worker uses `blocking_read`; it's a plain OS thread).
- `store.rs` — SQLite key/value store (settings, stable DeviceId, volume, persisted queue snapshot). Tokens go in the Windows Credential Manager (keyring), **not** SQLite — that includes the ListenBrainz token (`commands::listenbrainz_token()`; export/import strip it, `get_extras_settings` only returns a `listenbrainzConfigured` flag, never the token). The uninstaller's "Delete the application data" box removes them too: `NSIS_HOOK_PREUNINSTALL` (`installer/hooks.nsh`) runs `sonarune.exe --purge-credentials` when the box is ticked, not in an update and only if the exe has the uninstaller's version, and `credential_purge.rs` (handled in `run()` before the single-instance plugin and any window) deletes only generic credentials of the app's own name shapes (`<server>::<user>[::password].<service>` with an http(s) address, `listenbrainz.<service>`, plus `jellysic` for the real identifier). The names are built in one place (`commands::token_entry_name`, `password_entry_name`, `LISTENBRAINZ_ENTRY_NAME`); a new keyring entry needs a matching shape in `credential_purge.rs`, or it survives the uninstall. The hook leans on internals of the Tauri CLI's NSIS template (`$DeleteAppDataCheckboxState`, `$UpdateMode`, `CheckIfAppIsRunning`, `VERSIONWITHBUILD`): a renamed one only warns and silently skips the purge, so re-read the generated `installer.nsi` after a CLI update.
- `identity.rs` — whose stored data is whose. A server is its Jellyfin `Id` (`/System/Info/Public`), resolved by `commands::identify` *before* `install_session`, which makes no network request itself (a fresh sign-in without an id stays without; a renewal or restore falls back to the session's id or the one last seen at the address, kept in `server_address` with when it was first and last seen there). Analyses (`track_analysis.server_id`), the sonic index, the scan progress and the play history (`play_history.server_id`) key by it, plus the user id where per account. `identity::settle` (local, index-driven, on every install) gives pre-id rows to the server only on evidence: the signing-in account's own plays, analyses the account played under or that only this server can claim, and plays/analyses of an id this server replaced at its address (also the original coming back after a restored copy). Pre-id plays of other accounts stay id-less and show for their user id everywhere. A server releases what it owns, including id-less analyses at its own address; any listing claims them back within 30 days. Analyses keep `server_url` at the server's current address so 0.6.0/0.6.1 still read them; `Store::tidy` undoes stale ids those builds leave and deletes analyses released more than 30 days ago. Indexes are created outside the fatal path of `Store::open` (`Store::prepare`): building one reads the whole table, and a damaged page must cost speed, not the database. A playback analysis carries its server from the open (`StreamAuth.server` → `WaveformJob`), never from the store at write time.
- `proto.rs` — `jfimg://` protocol: authenticated, disk-cached cover art for the WebView (`http://jfimg.localhost/{itemId}/{tag}/{size}` on Windows). SMTC artwork reuses this disk cache via `file://` URLs.
- `player/tap.rs` — visualizer PCM bridge. A `TapSource` wrapper (outermost in the source chain) folds any channel layout to **stereo** (mono duplicated, surround channels mixed into both sides) and ships 2048-frame interleaved L/R frames over a Tauri IPC channel (`visualizer_subscribe` command, binary `InvokeResponseBody::Raw`; header: sample rate, channel count — decoded in `src/lib/visualizer/pcm.ts`). It runs on the audio callback thread, so sends go through a bounded queue to a forwarder thread (frames drop rather than block). Near-zero overhead when no visualizer is open (an atomic load and a sample counter, which keeps L/R aligned when a feed starts mid-stream). Frontend side: `src/lib/visualizer/` feeds a **muted** AudioWorklet graph (`static/visualizer-worklet.js`, stereo ring buffer with ~100 ms latency clamp) whose L/R reach Butterchurn's separate left/right analysers (MilkDrop WebGL presets) on the `/visualizer` route; energy/beat detection and the `SpectrumBar` FFT run on the mid signal.
- `commands.rs` — invoke surface (session, queue, settings). Queue mutations go through identity-checked commands (e.g. remove takes `(index, itemId, entryId)` to survive stale UI indices and tell two copies of a track apart; stop-after names the row by `entryId` too); a command that replaces the queue after a fetch takes `PlayerHandle::play_ticket()` before the fetch and sends through `play_queue`, an addition goes through `enqueue_turn()` + `enqueue()`, so the last play asked for wins and an addition lands behind the plays asked for before it; the queue panel shows the play order (`QueueSnapshot.order` while shuffling, `lib/queueOrder.ts`), so `queue_move` takes play-order positions (under shuffle it reorders only the shuffle order) while jump/remove take stored indices; shuffle/repeat/album-shuffle modes, played/duplicate cleanup, and a single-step queue undo (snapshot invalidated by any foreign queue edit) all live in the player worker. `commands_library.rs` (playlists — reorder/remove/transfer by `entryId`, not item id —, favorites, home rows, collections/BoxSets read-only) and `commands_discover.rs` (genres, A-Z scrubber via `nameLessThan` counts, similar artists, the Discover hub, decade rows, and dynamic **smart-view** queries — `SmartFilter` → server filters, materializable to a static playlist; `query_smart_view` lets the server page when it can evaluate the whole filter, otherwise it scans once — `addedSince` stops the scan early — and serves later pages from a short-lived id cache on the client) are separate modules; **all** server commands wrap `with_retry` (401 → probe → auto-relogin → retry). Work that runs outside a command — player opens (`spawn_open` → `open_track_renewing` on the open thread) and the Auto-DJ's fetches (`fetch_renewing`), the library watch, the sonic scan (at most every 10 min) and downloads — renews through `commands::renew_session` (the same probe and single-flight `relogin`, as a task of its own): once, then one retry; never after a sign-out or for an account that is no longer the signed-in one; a failed re-login answers background 401s for a minute. A sign-in and Quick Connect store their login and install the session under the same `relogin_gate` (`commit_sign_in`), and the start-up restore installs under it only what it found (`commit_restore`), so a re-login never interleaves with them. `relogin` runs against `SessionHost` (implemented by `AppState`), so its rules are unit-tested with an in-memory host.
- Home rows quirk: playback updates Played/PlayCount/DatePlayed only on **tracks**, never albums — `home_albums` queries tracks for the played-based rows and maps them to their albums.
- Playback reporting: the **play session belongs to one attempt at a track, not to the queue line**. `spawn_open` mints it, `source.rs` appends it to the `/Audio/{id}/universal` URL next to `startTimeTicks`, and the `/Sessions/Playing*` reports name the same one, so the server can correlate and kill transcode jobs. A reopen (seek in a transcode, device switch) continues the same session; a Play or Prefetch starts a new one — the server treats a session it saw stopped as a finished playback, so replaying an entry must not reuse it. The queue line's own `entry_id` is a separate, stable id that never leaves the app: the queue UI keys rows by it and tells two copies of the same track apart (it used to be the play session id, which is why old persisted queues are read through a serde alias).
- Extras (`player/scrobble.rs`, Auto-DJ in `player/mod.rs`): ListenBrainz playing-now on `report_start`, listen on `report_stopped` when the ≥4 min/≥50 % rule passes; Auto-DJ (track/artist/genre/album/playlist seed modes, plus sound: tracks that sound alike, with the instant mix as fallback) appends an instant mix when the last queued track enters its final 30 s (latched per seed; after a failed or empty answer the same seed asks again after 10 s, at most 3 times; resumes playback if the queue ended before the mix arrived, suppressed while an end-of-track sleep is armed). Sleep timer supports an optional fade-out (`player/fade.rs`).
- `download.rs` — original-file export (not offline cache): streams to a collision-safe `*.part` file and atomically renames on success; two concurrent slots (`Semaphore`), cancel (`AtomicBool` + `Notify`), and retry with an `attempt` generation (the attempt is part of the `.part` name so a retry cannot collide with a just-cancelled run's file). Events carry a list revision: `download:state` carries the whole list `{revision, tasks}` only when tasks come or go; progress (≤ every 500 ms, with a trailing send) and status changes go as `download:changed` with just the changed tasks, each stamped with the revision of its last change. `downloads.svelte.ts` keeps the newer copy by revision, drops older lists, and reads the list back when a change names a task it does not know; the panel shows the running downloads, the next `PANEL_ROWS` (50) waiting, the failed/cancelled ones (own section; `retry_failed_downloads` requeues all of them in one call) and the last 50 completed. The event sink and the session renewal (`commands::renew_session`) are hooks handed in by `new`, so the tests run without an `AppHandle` (see the test-binary gotcha above). Stale `.part` files older than 24 h are swept on startup.
- `cache.rs` — `CoverCache`: managed disk cache for `jfimg` cover art with a user-configurable MB limit and coalesced background LRU eviction (mtime order, evicts to 80 % headroom). `clear()` only removes regular files directly in the cache dir.
- Desktop/background: `tray.rs` (system tray + background mode — show/hide, current title, prev/play-pause/next; close-to-tray vs quit and start-minimized honor `DesktopSettings`; `tauri-plugin-single-instance`, registered first in `lib.rs`, hands a second launch over to the running window), `desktop.rs` (`DesktopSettings` in `store`: close behavior, start minimized, cache limit), `audio_devices.rs` (output device list + runtime fallback-device state for hotplug), `diagnostics.rs` (redacted 500-line log ring feeding the diagnostic export — URLs, credentials, absolute paths, and long hex ids are dropped wholesale; quoted dynamic values become `[value]`).

**Svelte (`src/`)**
- SvelteKit SPA (adapter-static, `ssr = false`), routes under `src/routes/`.
- `lib/state/*.svelte.ts` — runes-based stores. `player.svelte.ts` mirrors Rust state by listening to `player:state`, `player:queue` (the whole list, sent only when it or its order changed), `player:queue-index` (a track change: position and counts, applied in place), `player:error` events; UI never computes playback state itself. `player:error` carries `{ code, track, device, cause }` (`player/errors.rs`) and is worded by `lib/playerErrors.ts`. Command errors arrive as `ErrorReport` `{ code, status?, arg?, reason?, detail }` (`error.rs`: a base code per `AppError` variant, the `KNOWN` table for messages the UI words — matched where the error leaves, guarded by `every_known_message_is_still_raised` — or an area's own `update:`/`sonic:`/`preset:` code). Turn any rejection into text only through `lib/appErrors.ts` (`errorCause` inside `error_generic`, `errorMessage` standalone, `errorDetail` for area parsers, `isNotFound`); a new user-facing error message gets a `KNOWN` entry plus words there. Use `player.run(promise)` for fire-and-forget commands so rejections surface as the error banner. `player:error` causes carry the same `code`, and so do `DownloadTask.error` and the sonic scan's `ScanStatus.lastError`.
- Long lists: the playlist page (`PlaylistTrackList.svelte`) and its transfer dialog switch to virtua above `LONG_LIST_ROWS` (300, `lib/longList.ts`) and keep the animated FLIP list below. The page's `Virtualizer` scrolls in `<main>` with a measured `startMargin`; reorder by playlist position (`lib/dragReorder.ts`), the dragged row found again by its key at the drop; dragged and focused rows pinned via `keepMounted`; `dragend`/`drop` caught at the window; Back/Forward restore filter and position through SvelteKit `snapshot()`. The queue panel keeps its own limit (`FLIP_ROW_LIMIT`).
- `lib/api.ts` — typed `invoke()` wrappers; arg names are camelCase (Tauri maps to snake_case Rust params).
- `lib/types.ts` must stay in sync with the Rust DTOs (there is no codegen).
- Async fetches in routes need stale-response guards (capture the request id/param and compare before assigning state — see album page `$effect` and search `requestId` pattern). `lib/swr.ts` is the shared stale-while-revalidate cache: detail/overview routes render the last snapshot instantly, then background-refetch.
- Discovery/library routes: `/discover` (hub) with `/discover/{random,mixes,long-not-heard,decades,decade/[year],artists}` drill-downs, `/smart` (dynamic smart views, saved locally per server/user via `lib/smartViews.ts`), `/collections` + `/collection/[id]` (read-only BoxSets), `/recently-added`. Rust DTOs for these are in `lib/api/discovery.ts`.
- Global shortcuts (`lib/shortcuts.ts`, installed by the root layout for the signed-in shell) are **user-configurable**: bindings live in `lib/state/shortcuts.svelte.ts` (`shortcutSettings`, persisted, with conflict/reserved-key checks) and are edited in `ShortcutSettings.svelte`; `shortcuts.ts` resolves a `KeyboardEvent` → action via the store. Defaults: Space play/pause, Ctrl+K/Ctrl+P palette, Ctrl+←/→ prev/next, plus N/P, ←/→ seek, ↑/↓ volume, M/L/S/R. Handlers bail on `event.defaultPrevented` — row widgets that handle keys themselves just `preventDefault()`.
- View density / layout presets: `lib/state/layout.svelte.ts` + `LayoutSettings.svelte` (compact/comfortable lists, grid card size, sidebar width; one global layout, persisted under `sonarune.layout.v2`).
- Theming: `lib/theme.ts` + a pre-paint script in `app.html` (kept in sync by hand) set the accent vars from `localStorage["sonarune.theme"]` — there is no mode and no `data-theme`. `accentMode: "cover"` is the **default**: the accent is derived from the playing cover (`ambient.ts` → `setCoverHue`, lightness walked up to ≥3:1 against `--color-base`, last result cached under `sonarune.coverAccent.v2` for the pre-paint script) and fires `ACCENT_CHANGED` for canvas drawers; the stored fixed accent stays the fallback for grey artwork. `applyTheme` never paints `<html>` (frameless transparent window). `--cover-a`/`--cover-b` tint `.app-root::before`, which the opaque panels reduce to a thin colored seam around the chrome.
- Player UI building blocks: `SeekBar` (buffered range from `PlayerState.bufferedMs`, a whole-track waveform once `player/waveform.rs` has analysed the fully downloaded temp file — `player:waveform` event / `get_waveform` —, hover time, keyboard), `PlaybackProgress`, `TransportControls` — shared by the player bar and now playing. `Toaster` has success/info/error kinds (`toast.show(msg, { kind })`); page empty states use `EmptyState`; reorderable lists animate with `animate:listFlip` (`lib/motion.ts`).
- Extra frameless `WebviewWindow`s: the mini player on `/mini` and the visualizer projector on `/projector` (`lib/visualizer/projector.ts`, opened from the visualizer route onto a chosen monitor). The root layout renders those routes bare. **Command access is per window** (Tauri ACL): `build.rs` reads `generate_handler!` in `lib.rs`, declares every command as permissioned and generates the `main-window` set (all commands) into `src-tauri/permissions/main-window.toml` (git-ignored). `capabilities/main.json`, `mini.json` and `projector.json` each grant exactly one window; the mini and projector windows only get the hand-picked sets in `permissions/windows.toml`. A new command is available to the main window automatically — if `/mini` or `/projector` (or anything they import, like `player.init()` or the lyrics store) calls it, add `allow-<command-with-dashes>` to that window's set, or the call fails at runtime with "not allowed". A new window needs its own capability file. `acl_tests` in `lib.rs` checks the sets against the invoke handler.

## Manual check in the app

The gates prove the code builds and the tests pass, not that playback works.
For anything that touches playback, the session or the queue, run the app
against a real Jellyfin 10.11 server (or `scripts/devserver/`) and exercise
the flow: play an album, check that the Jellyfin dashboard shows the session,
restart the app to confirm the queue comes back. The red banner in the UI
surfaces player errors.
